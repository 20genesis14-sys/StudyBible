# 0016. Необязательные расширения формата модуля (до заморозки 1.0)

Статус: принято (05.10.2026).

## Контекст

Формат v1 (`docs/spec/05-module-format-v1.md`) хранит поток чтения.
Слова оригинала, подстрочник и критический аппарат сейчас лежат в
`spans.attrs` (`strong="…"`, `gr="…"`). В подстрочнике `int_en.sb` основной
текст — английская глосса, а греческое слово — атрибут: модель перевёрнута.
Критический аппарат и выравнивание хранить негде.

Условие пользователя: формат должен быть удобным на практике.
Конвертация чужих модулей (OSIS, USFM, Zefania, MyBible, BibleQuote, SWORD)
не должна быть трудной. Автор модуля не должен знать SQL.

## Решение

1. **Все расширения необязательны.** Модуль v1 без них остаётся правильным.
   Расширения не идут в `required`: старое приложение покажет текст и
   пропустит неизвестные таблицы (правило «Эволюция формата»).
2. **`meta.kind`** — тип модуля: `bible`, `interlinear`, `commentary`,
   `dictionary`, `layer` (слой без своего текста), `critical`.
   **`meta.features`** — список возможностей через запятую: `strongs`,
   `morph`, `tokens`, `alignment`, `variants`. Приложение строит лист «Слои»
   по `features`, а не по таблице в коде (`kModuleTags`).
3. **`tokens`** — слова оригинала: стих, порядок, форма, лемма, Стронг,
   морфология, глосса. Конвертер заполняет таблицу сам из того, что уже есть
   в источниках: OSIS `<w lemma morph>`, USFM `\w …|strong lemma x-morph\w*`,
   теги Стронга MyBible/BibleQuote. Отдельной работы от автора не нужно.
4. **`alignment`** — связь «токен оригинала ↔ слово перевода/глоссы».
   Вход для автора — простая таблица TSV: `ссылка  оригинал  глосса`
   (то же, что блоки «gloss / greek / pairs» в `build-interlinear.py`).
   Старый вид `gr="…"` читается дальше; конвертер переводит его в `tokens`.
5. **`variants` / `readings` / `witnesses`** — критический аппарат:
   место (стих + диапазон токенов), чтения, свидетели. Вход — TSV/JSON.
   Модуль-слой (`kind=layer`) может нести только аппарат без текста.
6. **`.sbz`** — контейнер для передачи: файл `.sb`, сжатый внешним
   кодеком. Внутри — обычная база SQLite. Приложение распаковывает файл
   при импорте. Заголовок: `magic "SBZ1"` (4 байта) + `codec_id` (1 байт)
   + payload. Кодеки: `0` = zstd (обязателен для читателя), `1` = brotli,
   `2` = xz (зарезервирован); прочие значения — на будущее, неизвестный
   кодек — понятная ошибка. Сжатие внутри базы — только для больших
   словарей и только через `required`.
7. **`entries`** — словарные статьи (модули `kind=dictionary`,
   06.10.2026). Плоская таблица: порядок `ord`, заголовок `headword`,
   нормализованная форма `norm` для поиска, текст статьи `text`.
   Модуль-словарь может не иметь книг и глав — `books` пустая,
   весь контент в `entries`. Вход автора — TSV `заголовок  текст`.
7б. **Инструменты для авторов.** `studybible module check` — проверка модуля
   с понятными сообщениями; `studybible module pack` — `.sb` → `.sbz`;
   шаблон TSV для подстрочника и аппарата; таблица соответствия полей
   чужих форматов в спецификации.

8. **Привязка сносок и ссылок к части стиха** (05.10.2026). Место span
   `f`/`x` в потоке сохраняется — относится и к сноскам, и к
   параллельным местам `x`. Необязательные поля: текст привязки
   (USFM `\fq`/`\xq`, OSIS `<catchWord>`) и буква части стиха (`\fr`/`\xo`,
   `1:1a`). Нет данных — ссылка к целому стиху; источники без позиции
   (MyBible, TSK) так и конвертируются.

9. **`meta.rights`** — флаги прав модуля (06.10.2026, закрывает вопрос
   № 15). Необязательный ключ, список запретов через запятую:
   `no-distribute` (не раздавать/не выкладывать), `no-net` (не отдавать
   по сети — web/API), `no-ai` (не передавать текст в ИИ-функции),
   `no-plugins` (не отдавать плагинам). Отсутствие ключа = всё разрешено.
   Это честное соглашение, не DRM; приложение уважает флаги в
   интерфейсе («поделиться файлом», экспорт, репозитории).

10. **Источник ** (06.10.2026). Добавлен вход `format=""`:
    пакет  (ZIP → `contents` → SQLite; `Content` —
    AES-CBC+zlib, ключ из языка/символа/года издания — форматная
    защита контейнера, не пароль). Даёт точную привязку сносок
    (`data-fref`) и параллельных мест (`data-ref` + `CitationBlock`)
    к части стиха — буква метки и слово привязки пишутся в `part`/`q`.
    Модули из  собираются только локально, `rights=no-distribute`.

11. **`fts` — встроенный поисковый индекс** (06.10.2026, по анализу
     `Word`/`SearchIndexBibleVerse`; закрывает вопрос № 23).
    Необязательная виртуальная таблица FTS5 внутри `.sb`:
    `fts(book UNINDEXED, chapter UNINDEXED, verse UNINDEXED, norm)`
    с токенизатором `unicode61`; `norm` — `for_search(текст стиха)`,
    та же нормализация, что у кэш-индекса. Собирается по запросу
    автора: `"fts": true` в modules.json (в `features` пишется `fts`).
    Читатель: таблица есть — ищет прямо по модулю; нет — строит
    кэш-индекс `.idx` как раньше (механизм не отменяется). Веб
    получает полноценный FTS5 вместо LIKE-скана по спанам.

    Версия нормализации (07.10.2026, вопрос № 14): правила
    `for_search` расширены (конечные буквы иврита → обычные,
    маккеф U+05BE → пробел, ς→σ), от чего индексы, построенные
    старыми правилами, несовместимы с новыми запросами.
    Константа `TOKENIZER_VERSION` в `search.rs` поднята до «2» —
    она входит в ключ кэша `.idx`, старые кэши перестраиваются
    сами. Для встроенной `fts` в `.sb` конвертер пишет
    `meta.norm_version = "2"`; у модуля с `fts`, но без ключа или
    с другой версией читатель игнорирует встроенный индекс и
    откатывается на кэш `.idx` (веб — на LIKE-скан). Модули со
    старым `fts` пересобирать не требуется.

12. **`marks` — метки времени** (06.10.2026). Необязательная таблица
    `marks(book, chapter, verse, seq, offset_ms, dur_ms, text)`:
    смещение от начала аудиодорожки главы в миллисекундах,
    `dur_ms` — длительность (NULL = до следующей метки), `text` —
    слово/фраза для подсветки и контроля. Заготовка под синхронизацию
    аудиобиблий и пословную подсветку TTS (Piper/Silero); сам 
    `` меток времени не несёт — источника для заполнения пока нет.
    Вход автора — TSV (`"marks"` в modules.json).

13. ** → модуль комментариев** (06.10.2026). У учебных изданий
    `VerseCommentary` + `VerseCommentaryMap` привязывают стих к
    комментарию; текст — срез `Document.Content` (тот же AES) по
    диапазону `DocumentParagraph` (`BeginParagraphOrdinal`/
    `EndParagraphOrdinal` = `ParagraphIndex`, позиции — байты UTF-8).
    Конвертер при `kind="commentary"` в modules.json собирает из того
    же `.` отдельный модуль `kind=commentary`: глава → блоки,
    каждый блок начинается меткой стиха `Span::Verse`. Публикация без
    `VerseCommentary` даёт пустой модуль — без ошибки.

14. **Источники MyBible и BibleQuote** (07.10.2026). Два новых входа
    конвертера, интерфейс как у  (`parse_file`/`parse_dir` →
    `Vec<usfm::Book>`):
    - `format="mybible"`: модуль `*.SQLite3` (таблицы `info`, `books`,
      `verses`; необязательные `stories` — заголовки разделов → `s1`).
      Номер книги MyBible (10 = Быт … 730 = Откр; неканонические —
      170 Тов, 180 Иудифь, 270 Прем, 280 Сир, 315 Посл Иер, 320 Вар,
      462/464/466 Макк, 145 МолМан, 165/468 Ездры и др.) отображается
      в код каталога;
      несопоставленный номер — ошибка, не пропуск. Разметка текста
      стиха: `<S>N</S>` — номер Стронга к предыдущему слову
      (`strong=` на спане `w`, префикс H/G по `info.strong_numbers_prefix`
      или завету), `<f>`/`<n>` — сноска, `<i>` — `\add`, `<J>` — `wj`,
      `<h>` — заголовок раздела, `<pb/>`/`<br/>` — абзац/перенос;
      прочие теги снимаются. При `kind="commentary"` читается
      `*.commentaries.SQLite3` (`commentaries` — диапазон стихов,
      привязка к первому стиху); при `kind="dictionary"` —
      `*.dictionary.SQLite3` (`dictionary(topic, definition)` →
      `entries`, как TSV словаря). В каталоге источника при сборке
      Библии сопутствующие `*.commentaries.`/`*.dictionary.` пропускаются.
    - `format="biblequote"`: каталог (или `.zip`) с `bibleqt.ini` —
      ключи `BibleName`, `Bible` (Y — Библия, N — комментарий),
      `ChapterSign`, `VerseSign`, `StrongNumbers`, `ChapterZero`,
      `BookQty` и по книге `PathName`/`FullName`/`ShortName`/`ChapterQty`.
      Кодировка файлов: UTF-8 (включая BOM) или windows-1251
      (`encoding_rs`). Книга → код по имени через каталог: строгое
      совпадение FullName → строгое ShortName → токены списка псевдонимов
      (порядок важен: «Первая книга Царств» — 1-я Самуила по синодальной
      нумерации, не 3-я Царств; порядковые числительные нормализуются
      в цифры). Несопоставленная — ошибка. При `Bible=N`/
      `kind="commentary"` — модуль комментариев: секции «Стихи a-b»/
      «Стих a»/«Verses a-b» привязываются к первому стиху диапазона
      (как gen_henry.py для comm-henry.sb); повторные маркеры на один
      стих склеиваются в одну запись; при `ChapterZero=Y` предисловие
      книги дописывается в первую секцию первой главы.
      Реальные отклонения формата (модуль Генри, BibleQuote-Modules):
      ini формата BibleQuote 7 — без `[секций]`, книги описаны
      повторяющимися группами ключей верхнего уровня (новая книга —
      от `PathName`); `ChapterSign=<!--PART-->`; `ShortName` — список
      псевдонимов через пробел.

## Последствия

- Простой модуль делается как раньше: USFM/OSIS → конвертер → `.sb`.
- Подстрочник и аппарат — тоже из простых текстовых таблиц.
- Схема расширений замораживается вместе с форматом в 1.0.
