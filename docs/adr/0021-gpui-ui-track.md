# 0021. Собственный GPU-интерфейс на базе форка GPUI (пост-1.0 трек)

Статус: принято как направление развития после 1.0 (решение
пользователя, 12.10.2026). Реализация не начата; Flutter остаётся
боевым фронтендом на всех платформах до готовности замены.

## Контекст

Пределы Flutter для нашей задачи подтверждены замерами: холодный старт
Windows release ~1.7–2.8 с при поле пустого приложения ~1.4–1.6 с,
APK ~80–126 МБ, wasm-веб без файловой системы. Глубже — модель:
тонкая типографика (текст над текстом, рубины, интерлиньяр, аппарат),
кастомные слои и сложные письменности упираются в закрытый текстовый
конвейер движка. Rust-ядро уже изолировано и UI-агностично — цена
миграции это цена только фронтенда.

Три равнозначных принципа будущего интерфейса (зафиксированы как
приёмочные критерии каждого этапа):

1. **Высочайшее качество текста** на всех платформах, в любом виде,
   на любом языке.
2. **Безупречная скорость и плавность** работы.
3. **Полная кастомизируемость и расширяемость**: слои, оверлеи,
   произвольные композиции («текст над текстом») — штатные
   примитивы рендера.

## Решение

Форк `gpui` + `gpui-kit` **в нашем репозитории** (crate
`apps/studybible-gpui` + платформенный crate): узкоспециализированный,
полный паритет с апстримом не цель, апстрим-обратно не требуется.
Лицензии проверены: `gpui` — Apache-2.0 (Zed), `gpui-kit` — Apache-2.0
(Longbridge); форк допустим с сохранением notice'ов.

**Своя система шейпинга** — rustybuzz (порт HarfBuzz) + наши шрифты
(Gentium, Literata, NotoSerifHebrew и др.) на всех платформах вместо
ОС-шейперов: идентичный вывод везде, работает на Android и wasm, где
системных шейперов нет, и даёт полный контроль над надстрочными/рубинами.
Платформенные DirectWrite/CoreText — фолбэк-опция, не основа.

**Объём каждого платформенного бэкенда** (не только «окно+рендер+текст»):
жизненный цикл, IME/клавиатура, жесты, буфер обмена, доступность
(AccessKit), аудио/TTS (SAPI, AVSpeechSynthesizer, android.speech.tts,
speech-dispatcher, Web Speech API), проигрывание аудиобиблий.

## Этапы

0. **Разведка** (первый слабый сигнал всей затеи): окно GPUI на
   Windows → `studybible-store` напрямую (без FRB-моста) → рендер
   главы: иврит RTL+огласовки, политонический греческий, кириллица,
   надстрочные, селекция по стихам. **Gate: нет эталонного качества
   сложных скриптов — трек останавливается здесь.**
1. Desktop-прототип читалки: скролл, выделение, панели, поиск,
   ссылки; пин версий форка.
2. Единый текстовый backend (rustybuzz + bundled fonts);
   золотые image-тесты строк на всех платформах.
3. Веб: wasm-путь (`gpui-pre-web` в gpui-kit — половина уже есть),
   wgpu→WebGL2/WebGPU или canvas2d; wasm-сборка store уже работает.
   До готовности — веб остаётся на Flutter.
4. Android: окно (winit/android-activity), wgpu (Vulkan/GLES),
   жесты/IME/clipboard/safe-areas, свой шейпер.
5. iOS: winit/UIKit, Metal-рендерер от macOS, CoreText или наш
   шейпер, UIKit-интеграция.
6. Паритет функций и миграция по платформам по мере готовности,
   не сразу; Flutter депрекейтится постепенно.

## Альтернативы (проверены, отклонены)

- **Makepad** — единственный Rust-UI с mobile+web сразу, но своя
  текстовая система с непроверенным качеством на наших скриптах и
  маленькая экосистема.
- **iced/floem/egui** — нет mobile; текст слабее GPUI-подхода.
- **Qt/Compose/Avalonia/React Native/Tauri** — каждый проигрывает по
  одному из трёх принципов или по покрытию платформ/весу; см. разбор
  в переписке 12.10.2026.
- **Совсем с нуля** (winit+wgpu+cosmic-text) — теряем готовую
  элементную модель, AccessKit, компоненты и чужую проверку продом.
- **Форк flutter_windows/engine** — движок уже собран с LTO/PGO
  апстримом, PGO для Dart AOT не существует; не окупается.

## Риски (зафиксированы)

- mobile-платформы дописываем мы сами: IME, сенсорная селекция,
  физика скролла, TalkBack/VoiceOver — самые тяжёлые участки;
- pre-1.0 апстрима: форк пиновый, апгрейды сознательные;
- два живых фронтенда на переходный период (Flutter + GPUI);
- аудио/TTS на собственном UI — наш код на каждой ОС.

## Связи

- ADR 0017 (голосовой движок): бэкенд `system` на GPUI реализуется
  через ОС-API; `neural`/`file` — в объёме бэкендов этапов 4–5.
- ADR 0018/0020: формат v2 и реестр вкладов не зависят от UI;
  слои реестра — модель будущих GPU-слоёв.
