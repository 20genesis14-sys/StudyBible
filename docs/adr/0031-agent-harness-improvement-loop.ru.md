# 0031. Петля улучшения агентской обвязки

Статус: принято (18.10.2026).

## Контекст

Правила для кодинг-агентов (`AGENTS.md`), записи памяти и скиллы
принимаются после инцидентов: баг проскочил — написали правило, и
ничто никогда не проверяет, что правило меняет поведение агента.
Навигационное правило — типичный пример: оно появилось потому, что
писали голые `Navigator.pop`, которые `PopScope(canPop: false)` молча
глотал.

Две опоры показывают, как замкнуть этот разрыв:

- прецедент в репозитории: трек Стронга (ADR 0025) замораживает
  промпты/скиллы до измерений, собирает квитанции прогонов и гейтит
  на отложенных корпусах;
- общий паттерн: Harness² (Google Research, arXiv:2610.14224) улучшает
  *обвязку вокруг фиксированной модели* через
  «предложи–прогони–скомпонуй», используя контраст поведения прогонов
  вместо ground truth.

## Решение

1. Принять четырёхшаговую петлю — предложи, прогони, сравни,
   скомпонуй — для всех изменений агентской обвязки. Владелец:
   [AGENT-HARNESS.ru.md](../AGENT-HARNESS.ru.md).
2. Записи [BUGS.md](../BUGS.md), которые агент мог поймать или
   предотвратить, несут строку `harness-gap:` с недостающим
   правилом/чеком/скиллом; это вход шага 1.
3. Механический слой: `scripts/check-agent-rules.ps1` выполняется как
   шаг `ci.ps1`. Первое правило NAV-1: выходы с маршрута экрана чтения
   — только через `_popRoute`/`_stackBack`/`_hierarchyBack`: голые
   `maybePop`/`pushReplacement` — нарушение во всех пяти файлах
   ридера, `Navigator…pop(` — в `reading_screen.dart` (в part-файлах
   `.pop()` закрывает диалоги — другие маршруты, вне правила);
   комментарий `// nav:` в строке — явное исключение под ревью. Новые
   правила рождаются только из записей `harness-gap:`, не из
   умозрений.
4. Поведенческий слой: замороженные карточки задач `evals/`
   воспроизводят реальные решённые задачи на исходных базовых
   коммитах (известный фикс = слабый эталон); `scripts/run-eval.ps1`
   готовит worktree и судит (ci.ps1, flutter analyze, agent-rules,
   чеки карточки); результаты — в `evals/results/`.
5. Вне скопа пока: headless-запуск агентов и автоматическое
   предложение/судейство. Прогон — интерактивная сессия агента;
   автоматизация возможна после того, как ручная петля докажет
   пользу.

## Последствия

- `ci.ps1` падает на нарушениях навигационного контракта в ридере.
- Три карточки evals замораживают воспроизводимую историю: пустое
  состояние ридера, C11 «Все вхождения» и фикс поиска по `.sbz` —
  каждая на своём базовом коммите, воспроизводимо неограниченно долго.
- Прогон стоит реальной сессии агента; прогоны — по требованию при
  появлении кандидата, не по расписанию.
- Принятые и отклонённые кандидаты оставляют следы (DECISIONS.md,
  `evals/results/`); запись «отклонено и почему» — хранилище уроков
  для будущих предложений.
