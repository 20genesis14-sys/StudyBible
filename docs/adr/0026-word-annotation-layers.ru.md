# 0026. Слои пометок на словах (BAB и подобные)

[English](0026-word-annotation-layers.md) | **Русский**

Статус: принято (2026-10-15); таблица реализована в `engbsb-bab.sb`.

## Контекст

Berean Annotated Bible (BAB) несёт 52 тыс. встроенных пометок поверх
текста BSB-2025: пояснения `(…)`, имена оригинала `{…}`,
альтернативные чтения `[…]`, буквальные переводы `\…/`,
перекрёстные ссылки и меры `<…>`, маркер множественного «вы» `⁺`.
Каждой пометке нужны: **якорное слово**, **тип**, **текст** и иногда
**цель** (dStrong-ключ, ссылки на стихи).

Существующие таблицы не подходят (про выбор словесной координаты —
ADR 0025):

- `links` — слово → dStrong; колонка `strong` потребляется читателем
  как ключ лексикона, а PK `(b,c,v,word)` запрещает две пометки на
  одно слово (`God{Elohim}⁺` — реальный случай);
- `spans` — символьные смещения, хрупкие при дрейфе текста — именно
  поэтому слой Стронга живёт на токенизаторе `w1`;
- `marks` — метки аудио; `xrefs_pack` — структурные цели ссылок.

## Решение

1. **Общая таблица** `annotations` внутри `.sb`-слоя (один слой на
   корпус пометок; первый — `engbsb-bab`):

```sql
CREATE TABLE annotations(
    book_id INTEGER NOT NULL, chapter INTEGER NOT NULL,
    verse INTEGER NOT NULL,
    word INTEGER NOT NULL,          -- индекс слова w1-якоря;
                                    -- -1 = пометка уровня стиха
    wlen INTEGER NOT NULL DEFAULT 1,-- покрыто слов (у BAB всегда 1)
    kind TEXT NOT NULL,             -- буква типа пометки (слой задаёт)
    text TEXT NOT NULL DEFAULT '',  -- содержимое (глосса, имя, …)
    target TEXT NOT NULL DEFAULT '',-- нормализованная цель (dStrong,
                                    -- 'JHN 1:1; HEB 11:3')
    conf INTEGER NOT NULL DEFAULT 0,-- уверенность привязки 0-10
    flags TEXT NOT NULL DEFAULT '', -- теги через запятую, см. ниже
    source TEXT NOT NULL DEFAULT ''
);
```

   Без первичного ключа (порядок rowid); индекс
   `(book_id, chapter, verse)`. `book_id`/`verse` — по целевому
   модулю, `word` — по его токенизатору `w1` (ADR 0025).

2. **Метаданные слоя**: `kind='layer'`, `features='annotations'`,
   `target_id`/`target_hash`/`tokenizer='w1'` как в ADR 0025.
   `draft=1` помечает черновой корпус (BAB — «early draft») —
   читатель может показывать значок draft.

3. **Словарь `kind` — свой у каждого слоя**; для `engbsb-bab`:
   `e` акцент `(…)`, `o` слово оригинала `{…}`, `a` вариант `[…]`,
   `l` буквальный перевод `\…/`, `x` ссылка и `m` мера `<…>`
   (нотация `<…>` режется на `x`+`m`), `p` множественное «вы» `⁺`.

4. **Словарь `flags`** (через запятую):
   `dup` — содержимое уже дословно есть в тексте цели (собственные
   скобки BSB, проглоченные как `e`) — не отображать; `near` —
   якорное слово не пережило diff источника/цели, привязка к
   ближайшему выровненному слову слева; `verse` — выровненного слова
   нет, пометка на уровне стиха (`word=-1`); `noent` — имя `{…}` без
   разрешённого dStrong (ждёт связи с knowledge-graph).

5. **Сборщик**: `D:\StudyBible-data\work\bab\build_bab.py` — разбор
   `bab.txt`, выравнивание слов BAB на слова модуля через LCS (та же
   процедура, что у перепривязки Стронга), якорь — последнее слово,
   завершившееся до/на позиции пометки, разрез `<…>` на `x`/`m`,
   однозначные `{…}`-имена → dStrong. Квитанция:
   `work/bab/receipt-bab.json`.

## Последствия

- Контракт не привязан к BAB: любой будущий слой встроенных пометок
  (глоссарии, заметки study-Bible, варианты перевода) переиспользует
  `annotations` со своим словарём `kind`.
- Поддержка в мосте/рендерере — отдельная задача: пометки можно
  инъектировать как стиховые ноты (готовый `inject_verse_note`), как
  `strong`-атрибут (`o` с dStrong-целью) или как `bab=`-атрибут с
  бейдж-виджетом — вопрос точности отображения отложен (BAB — draft).
- Пометки `word=-1` деградируют до стихового уровня без потерь.
