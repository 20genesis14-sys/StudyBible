# 0023. Параллельные места как общий модуль-слой

[English](0023-xrefs-layer.md) | **Русский**

Статус: принято (10.10.2026).

## Контекст

Перекрёстные ссылки (набор OpenBible, ~29,4 тыс.) вшивались в каждый
модуль при сборке через `inject_xrefs` — один и тот же набор
дублировался в каждый перевод: ~2 МБ `x`-спанов на модуль, шаг сборки
на каждый модуль, ссылки в `content_hash`. Перевод без родных
параллельных мог получить их только пересборкой.

По сути параллельные места — не часть текста перевода, а отдельный слой
данных, как словарь. В формате уже есть `meta.kind="layer"` (ADR 0016)
для модулей без собственного текста.

## Решение

1. **Модуль-слой `openbible-xrefs`** — `.sb` с `kind="layer"`,
   `features="xrefs"`, без своих глав и стихов. Ссылки — обычные
   `x`-спаны: `(book_id, chapter, verse, seq, kind='x', caller='+',
   text)`, `block=0`. В `text` — языконезависимые OSIS-ссылки
   (`Ps.104.30-Ps.104.31`); подписи локализуются приложением по
   профилю названий при показе.
2. **Слияние в читателе** — если в модуле нет своих `x`-спанов и слой
   включён (настройка `xrefLayer`, по умолчанию вкл.), `chapter_doc`
   подмешивает ссылки слоя как спаны `Note{x}` в конец каждого стиха.
   Модули с собственными `x`-спанами не трогаются — слой лишь
   заполняет пробел.
3. **Поставка**: `openbible-xrefs.sbz` лежит в `assets/modules` и
   сидируется в каталог данных как встроенные переводы; в списках
   переводов не показывается (`kind="layer"`).
4. **Сборка**: `studybible module xrefs <cross_references.txt> --top N`
   строит слой; `inject_xrefs` остаётся для модулей со встроенными
   ссылками (родные параллельные перевода по-прежнему внутри него).
5. Координаты слоя — `eng`; конверсия в версификацию целевого модуля —
   при чтении через `Versification::convert`.

## Последствия

- Каждый модуль теряет ~2 МБ дублированных ссылок; пересборка
  `russyn`/`KJV` больше не требует `inject_xrefs`.
- Обновление одного набора обновляет все переводы.
- Без файла слоя модуль просто не показывает параллельных — как модуль
  без `x`-спанов сейчас. Ссылки больше не входят в `content_hash`.
- Подписи OSIS (`Ps.104.30`) при показе переводятся в локаль интерфейса;
  хранимая форма остаётся языконезависимой.
