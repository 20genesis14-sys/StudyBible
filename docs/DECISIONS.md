# Принятые решения

Редакция 2. Источник истины по решениям проекта; краткие обоснования — в `adr/`, оглавление — в `SPEC.md`.

## Цели
Две цели, обе равноценные:  
1. Чтение: простое, удобное, быстрое кроссплатформенное приложение для чтения Библии.  
2. Изучение: параллельные места, лексикон Стронга, сравнение переводов, подстрочники,  
   оригиналы, комментарии и т. д.  
Порядок работ: сначала чтение (Alpha 1), затем изучение (Alpha 2). Цель 1 при этом не важнее цели 2.  

## Принципы
Данные пользователя (заметки, выделения, закладки) хранятся только на его устройстве.  
Мы нигде их не храним, телеметрии нет. Всё, что пользователь загружает сам,  
остаётся на его ответственности.  
Интерфейс заменяемый: ядро от него не зависит, интерфейс можно переписать.  

## Измеримые требования (десктоп, верхняя граница, быстрее можно, медленнее нельзя)
Открытие главы — не более 50 мс. Поиск по всей Библии — не более 200 мс.  
Холодный старт — не более 1 с. Память — не более 150 МБ при одном открытом переводе.  
Минимальные версии ОС: Windows 10, macOS 12, Ubuntu 22.04, Android 8 (API 26), iOS 15.
Windows 7/8 не поддерживаем: Rust с версии 1.78 собирает под Windows только для 10 и новее.  

## Платформы и технологии
Платформы: Windows, macOS, Linux, Android, iOS, веб.  
Порядок: десктоп → Android, iOS → веб в самом конце.  
На десктопе и мобильных нет JS и webview. На вебе JS-оболочка (wasm-bindgen) неизбежна,  
поэтому ограничение на веб не распространяется.  
Ядро на Rust, архитектура «порты и адаптеры». Домен только в Rust.  
Связка с интерфейсом одна и тонкая, выбирается вместе с интерфейсом  
(Slint — прямой вызов Rust; Flutter — flutter_rust_bridge).  
UniFFI и C ABI появятся, только когда у них будет реальный потребитель.  
Порты ядра: хранилище модулей, пользовательская база, кэш индексов, речь;  
позже — репозитории и сеть.  
Путь к файлу — адаптер десктопа; на Android — content URI; на вебе — OPFS (позже).  
Основа под веб: в домене нет std::fs, главный поток не блокируется.  
В CI с Этапа 0 есть одна проверка: ядро компилируется под wasm32, без запуска тестов.  
Сборки и тесты под Android и iOS добавляются к Beta. Веб финализируем и тестируем в самом конце.  

## Интерфейс
Интерфейс — **Flutter**, связка — flutter_rust_bridge (решение по пробному
экрану, ADR 0012 → ADR 0013). Пробный экран на Slint не строится.
Чек-лист пробного экрана (критерии приёмки интерфейса и дальше):  
- глава с абзацами, поэзией, заголовком, сноской и словами Иисуса;
- выделение мышью и клавиатурой;
- смешанный иврит и русский;
- клик по слову;
- виртуализованная книга целиком;
- две панели с синхронной прокруткой;
- работа с программой чтения с экрана;
- масштаб шрифта ОС.
Синхронная прокрутка: соответствие «якорь ↔ пиксели» и правило ведущей панели.  
Шрифты для иврита с кантилляцией и политонического греческого — встроенные, под OFL.  
Языки интерфейса: русский и английский сразу, остальные — через файлы локализации.  

### Дизайн-система и навигация (по прототипу, ADR 0013)
- Сетка 66 книг непрерывная, два блока (Еврейские Писания / Христианские
  Греческие Писания); группы книг — только цветом плитки (10 групп,
  контраст ≥ 4.5:1). Главы — сетка; галочка прочитанного, полоса прогресса
  книги, маркер «продолжить».
- Глава: свайп и клавиши ← → через границу книг; номера стихов цветом группы
  и полужирные; тап по стиху → панель действий + боковая панель сносок
  (мобильная — шторка); двойной тап → сравнение переводов.
- Режимы вёрстки: абзацы (красная строка) / «стих на строку»; масштаб шрифта
  слайдером и Ctrl+колёсико; опция узкой колонки «Чтение».
- Темы: светлая «бумага» — палитра ADR 0015 (тёплая сепия, тушь,
  акцент — киноварь), тёмная «для глаз», AMOLED (в тёмных темах киноварь
  даётся осветлённым оттенком).
  Шрифты чтения: встроенные Literata и Gentium Book Plus, системный — опция.
- Выбор стиха — тумблер в настройках; нижнее меню: Главная / Библия /
  График чтения / Модули / Настройки (вкладка «Словари» переименована
  в «Модули» — там управление текстовыми модулями и словарями).
- «График чтения» — экран прогресса: общий счётчик прочитанных глав и
  полосы по разделам (ВЗ/НЗ) и книгам; блок «Заметки» на той же странице.
- Панели экрана чтения: «жидкое стекло» — размытие σ2 + заливка card 0.3
  + светлый блик по краю к контенту (apple-style); текст под панелью
  читается. Раньше: σ8 + 0.5 выглядели сплошной заливкой.
  Верхняя панель: поле поиска всегда полностью на экране, название книги
  режется до ~12 знаков с многоточием — длинные имена не выталкивают поиск.
  Нижняя панель на узком экране — без стрелок глав (листается свайпами);
  действия — крупные иконки с цветовыми акцентами. Диалог заметки: действия
  иконками (три текстовые кнопки в столбик перекрывали поля под клавиатурой).
  Чтение вслух: мини-плеер над нижней панелью (стих ‹/›, пауза, стоп, место,
  ползунок прогресса по стихам главы — перетаскивается) и медиа-сессия
  Android (audio_service — уведомление, шторка, audio focus). Чтение идёт
  в фоне (foreground-сервис mediaPlayback, WAKE_LOCK); смахивание
  приложения из «недавних» (onTaskRemoved) завершает сеанс чтения.
- Жизненный цикл контроллеров диалогов: TextEditingController должен жить
  в State диалога (dispose в State.dispose). Владение снаружи showDialog
  (создать → await → dispose сразу после возврата) приводило к assert
  '_dependents.isEmpty' / 'child.owner == owner': зависимые элементы
  InputDecorator остаются активными, когда dispose дергает список
  посреди демонтажа route. То же правило — действия из контекстного меню
  выделения запускаем в конце кадра после hideToolbar.
- Прокрутка к стиху при переходе (выбор стиха, стих дня, сноски):
  якорь стиха — нулевой WidgetSpan на номере стиха внутри текста
  (точное место стиха, а не начало абзаца); для стиха без живого
  якоря прокрутка берёт ближайший прикреплённый стих до целевого
  (_ctxForVerse). В ленте «Книга» главы строятся лениво — итеративный
  _seekVerseBook: на каждой итерации принудительный кадр
  (scheduleFrameCallback + addPostFrameCallback — на статичном экране
  endOfFrame не наступает никогда, a jumpTo без кадра двигает позицию
  только «на бумаге»); якорь вне комфортной зоны 10–60% viewport —
  прямой jumpTo на 15% (ensureVisible на ~2 fps не прогрессирует);
  якоря нет — прыжок к оценке доли ленты ext·(ch-1)/total для далёкой
  главы или шаг на viewport для соседней (индексная оценка на
  неравномерных главах систематически перелетает); выход по двум
  стабильным кадрам подряд или по повтору оценки. «Протухшие» ключи
  выкинутых из viewport глав не считаются построенными
  (currentContext == null → пропуск).
- Листание глав — постраничное, как в читалках: горизонтальный драг
  тянет текущую страницу за пальцем, рядом подъезжает входящая глава
  (обе с текстом: цель подгружается ensureChapter при старте драга;
  у peek-страницы нет якорей и общих ключей — дубль GlobalKey).
  Задержанный палец держит страницу на месте; отпускание — доводит
  переход при сдвиге >25% ширины или броске ~400 px/s, иначе откат
  (Curves.easeOutCubic, ~190 мс). В режиме «книга» страница —
  переход к соседней книге. Цель перехода — _goTarget, общая
  с _go без побочек. Структура: Listener (не GestureDetector —
  иначе ломается выделение текста) с трекингом pointer move.
- Сноски: библейские ссылки в тексте («Быт 1:1», «Быт 2:19») — гиперссылки;
  переход открывает главу и прокручивает к стиху, перевод сохраняется.
- Настройки персистентны: сохраняются JSON'ом в userdata как запись
  kind=mark, module='settings', book='SET' (допустимый якорь без привязки
  к тексту). Settings.load() при старте; Settings.update() сохраняет после
  завершения загрузки (_loaded — не затирать дефолтами сохранённое).
- Основной перевод: settings.defaultModule, по умолчанию 'russyn';
  helper mainModuleId() в data.dart — откат на первый доступный модуль,
  если id настройки отсутствует на платформе. Выбор в «Настройках»
  (сохраняется, действует при запуске) и чипом «Перевод» на верхней
  панели вкладки «Библия» (шторка списка модулей, выбор сразу меняет
  загруженный модуль сетки книг). Все переходы без явного moduleId
  (сетка глав, поиск, чтение) используют mainModuleId().
- История сквозная по всем модулям: записи kind=mark с префиксом text
  'hist' — 'hist' (глава: module+book+chapter+verse), 'hist:dict' (статья
  словаря: context 'H3117|слово'), 'hist:search' (запрос: context=query).
  Пишется при открытии главы, смене перевода, поиске, развороте статьи
  словаря и открытии карточки Стронга. Экран «История» показывает ленту
  всех типов с именем модуля; тап восстанавливает контекст (глава+стих
  в том переводе, словарь → карточка, поиск → экран с тем же запросом).
- Словарь: Strong's Exhaustive Concordance (иврит + греческий) из
  openscriptures/strongs, XML под CC-BY-SA — текст Стронга 1890–94 в
  общественном достоянии; атрибуция Open Scriptures показана в разделе
  «Модули». Лежит компактным JSON (14 298 статей) в assets/data/strongs.json.
  Поиск по номеру/лемме/определению; тап по слову с номером Стронга в
  тексте модуля открывает карточку статьи.
- Русский словарь Стронга: редакция Ю. А. Цыганкова («Библия для всех»,
  СПб., 2005) — 8 674 статей иврита + 5 523 греческих; источник данных —
  azbyka.ru (через репозиторий ChurchPresenter). Это копирайтный перевод:
  как пользовательские данные лежит в STUDYBIBLE_DATA/dictionaries/
  strongs_ru.json (генератор tools/gen_strongs_ru.py), НЕ в репозитории
  и НЕ в публичной сборке. При наличии файла русские определения
  накладываются поверх английского словаря (лемма, транслитерация,
  произношение — из русской статьи; происхождение, пункты и KJV —
  из английской); без файла работает английский. Локальная web-сборка
  читает тот же файл из dicts/strongs_ru.json.
- Web-раздача модулей: деплоим `modules/*.sb.gz` (gzip -9, ~60% легче —
  313→123 МБ) плюс index.json со списком; `native_bridge_web` при открытии
  модуля сначала качает `<path>.gz` и распаковывает браузерным
  DecompressionStream, при 404 — сырой .sb (локальная разработка не ломается).
  Причина: передача большого каталога на хостинг флаки-падает.
- Неканонические книги модуля: сетка книг показывает книги модуля вне
  каталога 66 отдельной секцией «НЕКАНОНИЧЕСКИЕ КНИГИ» (группа
  BookGroup.other, серый цвет); навигация между книгами на экране
  чтения идёт по порядку книг модуля (books модуля, а не kCatalog).
  Тесты намеренно не пишем (указание пользователя) — поведение
  задокументировано здесь; проверка будет на реальном модуле LXX.
- Модули-подстрочники (слово-над-словом): каждая пара «перевод/оригинал»
  — текстовый спан style='w', текст — глосса, слово оригинала — в
  атрибуте attrs `gr="…"`. Признак meta: `interlinear='1'`. Экран
  чтения рисует такие главы колонками «глосса над оригиналом» (шрифт
  оригинала по языку спана; для gr= — GentiumBookPlus) во всех
  режимах вёрстки; в строчном сравнении тот же рендер. Формат
  источника int-en: блоки «gloss / greek / pairs» — конвертер
  scripts/build-interlinear.py. Сам модуль int_en (Kingdom
  Interlinear) — личный модуль пользователя: в репозиторий и
  сборки не входит, ставится через «Импорт .sb».

### Визуальный язык и модель интерфейса (05.10.2026, ADR 0014, 0015)
- Интерфейс описывается данными: Workspace → Pane → Layer (JSON в userdata).
  Экран чтения разделён на части `reader_controller.dart`,
  `chapter_renderer.dart`, `reader_pane.dart`, `reader_chrome.dart`,
  `page_swipe.dart`, `tts_service.dart`, `notes_sheet.dart`,
  `reader_dialogs.dart`. На первом шаге это `part`-расширения состояния
  экрана; вид и поведение не меняются. Редактор раскладки — после 1.0,
  модель — сейчас (ADR 0014).
- Визуальный язык «книга и киноварь»: тёплая бумага, тушь, один красный акцент;
  буквица номера главы, надстрочные номера стихов (ADR 0015).
- Режимы «Чтение» (чистый текст) и «Изучение» (стих на строку, точка на поле,
  буквы сносок) — один переключатель в верхней панели.
- Лист «Слои» вместо отдельных кнопок сравнения, подстрочника и сносок.
- Нижняя панель чтения: Перевод · Слои · Слушать · Ещё (монохромно, градиент
  фона вместо размытия).
- Нижняя навигация — вариант А: Главная · Библия · План · Записи · Библиотека.
  Поиск — поле вверху Главной и кнопка «Поиск» в нижней панели чтения
  (плавающее поле над панелью); на Библии поля поиска нет — сетка
  книг без фильтра. Настройки — шестерёнка на Главной. На Главной —
  карточка «Сегодня по плану».
  Альтернатива Б (Сегодня · Библия · Поиск · Записи · Библиотека, план —
  карточкой на Главной) записана в ADR 0015 для возможного возврата.
- Экран «План» (бывший «График»): активный план с кольцом прогресса и
  серией дней, полоса недели, список «Сегодня» с отметками, «Карта
  прочитанного» (столбик = книга, ширина = число глав, цвет = группа),
  другие планы. Макет `docs/design/06-plan.png`.
- Планы чтения в первой версии (05.10.2026): «Хронологический» (вся Библия
  в порядке событий) и «Евангелия» (Мф, Мк, Лк, Ин — 89 глав). Другие планы
  пользователь добавит позже. План — данные (JSON: день → список глав или
  диапазонов), не код: новый план добавляется файлом
  (assets/data/plans.json). Источник хронологического порядка —
  годовой график sbr_U.pdf от пользователя (вопрос № 38 закрыт):
  OCR по колонкам, покрытие 66 книг проверено тестом. Выбор плана и
  дата старта — в настройках; день выполнен, когда все его главы
  помечены прочитанными.
- Сетка книг: раскладка и насыщенные плитки по ADR 0013 остаются.
  Насыщенность цветов групп ниже на 15–20 % (контраст белого текста ≥ 4.5:1
  сохраняется). Полное имя книги под сокращением — опция в настройках,
  кегль ≥ 11 sp. Тональные плитки (макет 3) отклонены.
- Типографика чтения (цель до Beta / в Beta): кегль по умолчанию 20–21 sp;
  вариативная Literata с осью `opsz`; выключка влево по умолчанию,
  по ширине — только с переносами; PT Serif (OFL) в списке шрифтов.
- Сноски: по умолчанию надстрочная буква у слова, без пробела, неразрывно
  (вариант А); пунктир под словом без знака (вариант Б) — если в модуле есть
  текст привязки. В «Чтении» знаки скрыты; тап → карточка; зона нажатия
  маркера ~28×28 dp (невидимый паддинг; 44 dp внутри строки ломали бы
  межстрочье). Макет `docs/design/07-footnote-variants.png`.
  Карточка — высокая (~75 % экрана): ссылки остаются гиперссылками,
  под каждой — текст стиха(ов); перевод текстов настраивается
  («Перевод параллельных мест», по умолчанию основной). Размер текста
  сносок и параллельных — отдельные ползунки (footScale/xrefScale)
  в листе «Шрифт и тема» и в «Настройках».
- Тап по стиху/номеру стиха — всплывающее меню у места нажатия
  (не панель внизу): Копировать, Выделить, Заметка, Теги, Закладка,
  Сравнить, Параллельные (если есть), Поделиться.
- «Сравнить» — отдельный экран «стих во всех переводах»: карточка на
  перевод с текстом стиха, тап → переход к стиху в этом переводе;
  список переводов — чекбоксы в настройках (все = по умолчанию).
- Заметки: отдельные название и текст (хранение «заголовок\x1Fтекст»
  в поле text записи); правка и удаление в «Записях»; заметка к стиху
  ведёт на её место по тапу.
- «Шрифт и тема» в меню «Ещё» — локальный лист (тема, шрифт, размер
  текста и сносок), без перехода в «Настройки».
- Поиск по тексту — без выбора перевода: ищется в том переводе,
  откуда поиск открыт (из чтения — текущий, иначе — основной).
- Web: сборка `--wasm` (рендерер skwasm); многопоточный растр через
  COOP/COEP (serve_web.py → crossOriginIsolated, SharedArrayBuffer);
  JS+CanvasKit фоллбэк для старых браузеров (flutter_bootstrap.js
  выбирает сам); serve_web.py отдаёт gzip.
- Параллельные места — по частям стиха: место знака и текст привязки
  сохраняются при конвертации; лист группирует ссылки по частям (`1:1a`);
  нет привязки — ссылка к целому стиху. Макет `docs/design/08-xrefs-verse-parts.png`.
- Макеты: `docs/design/` (описание — `docs/design/README.md`).
- Движок тем и шрифтов (после 1.0): пользовательские темы — редактор
  палитры (фон/карточки/текст/акцент/края) поверх светлой или тёмной
  базы, именованные темы, экспорт/импорт файлом; пользовательские
  шрифты — добавление TTF/OTF в список шрифтов чтения.
- Статистика чтения (после 1.0): встроенная локальная телеметрия —
  среднее глав/стихов в день, время в приложении по дням и неделям,

## Данные и модули
Модуль — собственный формат SQLite: текст, разметка, токены, метаданные.  
FTS-индекс не входит в модуль. Он лежит в локальном кэше, его строит приложение или конвертер.  
Ключ кэша — хэш содержимого модуля плюс версия токенизатора.  
Модуль — недоверенный файл: только чтение, SQLITE_DBCONFIG_DEFENSIVE, trusted_schema=OFF,  
проверка схемы и версии формата.  
Пользовательские данные — отдельная база с версией схемы и миграциями.  
Метаданные модуля: id, версия, язык (BCP 47), направление письма, версификация,  
профиль канона, профиль названий книг, лицензия и атрибуция, флаги прав  
(копирование, сеть, ИИ, плагины — заготовка на будущее).  
Кодировка: UTF-8. Переводы хранятся в NFC. Оригиналы хранятся как в источнике:  
для иврита NFC переставляет огласовки, поэтому нормализация применяется только к поисковым ключам.  

Координаты:  
- стих — (версификация, книга OSIS, глава, стих, необязательный сегмент);
- слово оригинала — стабильный id токена в именованном издании;
- выравнивание — связи многие-ко-многим, допускаются слова без пары;
- позиция в переводе — стих + смещение символов + контрольный фрагмент текста;
- нестиховое содержимое (введение, статья, комментарий на диапазон) — id элемента.
Пользовательская запись хранит id и версию модуля, тип указателя  
и всегда — стиховую координату как запасную. В схеме v1 версии модуля  
и версификации ещё нет (открытый вопрос № 12).  
При обновлении модуля: карта перехода старых id на новые; если её нет — перепривязка  
по контрольному фрагменту; если не удалось — откат к стиху.  

Версификации — данные: Paratext под MIT (org, eng, lxx, vul, rso, rsc) плюс сверка с TVTMS.  
Импорт с эталонными тестами. Отображения учитывают 1→N, N→1, части стихов и «нет соответствия».  
Искажённая строка-соответствие не должна рушить файл: парсер пропускает её и записывает  
в `skipped()` (обнаружено в vul.vrs: `DAG 3:52-23` — вероятная опечатка «53»).  
Для таких стихов действует правило по умолчанию — тождественное соответствие.  
Буквенный сегмент стиха (`1:1a`) при разборе отбрасывается — открытый вопрос № 13.  
Метка версификации модуля — нумерация самого файла. russyn — `rsc`.  
eBible engwebp и eng-kjv2006 — `eng` (Мал 4, Иоил 2:28–32), не `org`:  
при метке `org` эти стихи не открывались ссылкой (поправка 2026-10-02).  
Соответствие кодов Paratext/USFM и OSIS — явная таблица-данные.  
Книги вне org (Пс 151 и др.) получают координату в своей версификации.  
Для MyBible и BibleQuote версификация при импорте определяется эвристикой с подтверждением.

## Формат модуля v1
- Поток чтения: глава — последовательность блоков (абзац, поэзия с уровнями, заголовок раздела)
  и строчных промежутков (маркер стиха, добавленные слова, слова Иисуса, имя Бога,  
  выноска сноски, ссылка). Перечисленное подмножество USFM проходит круговое преобразование.  
- Сноски, перекрёстные ссылки.
- Заголовки разделов — отдельный слой.
- Токены оригинала: лемма, морфология, Стронг, ктив/кере.
- Выравнивание.
- Словари с несколькими ключами (Стронг, лемма, слово).
- Комментарии к стиху и к диапазону.
- Приложения: введения, глоссарий, таблицы, изображения с подписью (карты — как изображения).
- Общий механизм необязательных версионируемых слоёв.
- Флаг «требует разблокировки» — заготовка на будущее.
Флаги прав решены (вопрос № 15 закрыт): необязательный ключ
`meta.rights` = список запретов через запятую — `no-distribute`, `no-net`,
`no-ai`, `no-plugins`. Отсутствие ключа — всё разрешено; соглашение, не DRM.
Необязательные расширения до заморозки (ADR 0016, 05–06.10.2026): `meta.kind`,
`meta.features`, `meta.rights`, таблицы `tokens`, `alignment`,
`variants`/`readings`/`witnesses`, `entries` (словарные модули
`kind=dictionary`, вход — TSV `заголовок → текст`), привязка сносок и
параллельных мест к части стиха, контейнер передачи `.sbz` (zstd + brotli,
байт кодека — на будущее). Условие: конвертация чужих модулей и создание
своих остаются простыми — конвертер заполняет таблицы сам, автор пишет USFM/OSIS
и простые TSV, без SQL. Расширения не идут в `required`.
Заморозка в 1.0 означает запрет менять или удалять существующие поля.  
Новое — только необязательные таблицы. В модуле хранятся версия формата  
и список обязательных возможностей.  

## Конвертер
Библиотека (crate) плюс оболочка; на мобильных используется как библиотека. В нашем коде нет GPL.  
SWORD — через необязательную внешнюю программу, выгружающую OSIS.  
Порядок: OSIS, USFM → Zefania → MyBible, BibleQuote → SWORD → MySword, e-Sword.  
Сборка модулей из USFM: `studybible module build` читает `data/modules.json`
(метаданные и id источника) и пишет `*.sb` в `<корень данных>\modules`
(обёртка — `scripts/build-modules.ps1`). Уже существующий файл не заменяется:
запись создаёт схему заново и останавливается, старый `*.sb` нужно убрать самому.
USFM-файлы книг берутся по имени в порядке
сортировки; нумерация файлов eBible даёт канонический порядок (FRT первым, GLO последним).  
Ограничения USFM-разбора v1: объединённые стихи (`\v 1-2`) берутся по первому номеру;
вложенные стили хранят только внутренний (`\wj \w…` → `w`); в сносках и ссылках
метки `fr`, `xo`, `fv` отбрасываются — текст цели ссылки пока не сохраняется.

## Поиск
Индекс FTS5 в кэше — `studybible_store::SearchIndex`, файл `<модуль>.idx` рядом с модулем
(или флаг `--cache`). Ключ кэша — `content_hash` модуля + версия токенизатора (`1`);
при смене нормализации версия растёт и кэш перестраивается. Таблица `fts` хранит
нормализованный текст (`core::normalize::for_search`: регистр, ё=е, дореформенные
буквы, диакритика через NFD), координаты стиха — неиндексируемыми столбцами.
Запрос: слова нормализуются и соединяются через AND, порядок bm25.  
Сделано в MVP: точная форма (`for_search`) и AND. Стемминг, лемматизация, фраза,
NEAR, начало слова, ограничение области и поиск по многим модулям — ещё нет.  
Уровни нормализации (цель; в `for_search` сейчас только то, что сказано ниже):  
- русский — регистр; ё = е; ударения и мягкие переносы; дореформенные ѣ, і, ѳ, ѵ;
  «й» сохраняется отдельно («мой» ≠ «мои») — NFD разлагает её в «и»+бреве,
  поэтому её прячем за символ частной области до разложения;
- иврит — теамим и огласовки снимаются (NFD). Конечные буквы и маккеф ещё нет
  (открытый вопрос № 14);
- греческий — регистр, ударения и придыхания, подписная йота (через NFD).
  Конечная сигма к обычной не сводится (вопрос № 14).
Дальше по плану. Переводы: точная форма уже есть; стемминг (Snowball для русского и английского)
и лемматизация (словарь OpenCorpora) — позже.  
Оригиналы: поиск по лемме, Стронгу и морфологии из данных, без стемминга.  
Фраза, NEAR, начало слова, ограничение области (книги, канон, диапазон).  
Поиск по многим модулям: результаты группируются по модулям, bm25 разных индексов не смешивается.  

## Вывод
Несколько переводов колонками или строками, выравнивание через карты версификаций.  
Раскладки экрана — данные.  
Копирование стиха: текст, ссылка, краткое имя перевода, атрибуция.  

## Голос и доступность
(а) Программы чтения с экрана: NVDA, JAWS, Экранный диктор, VoiceOver, TalkBack, Orca.  
Это требование к первому текстовому виджету (Alpha 1) и критерий выбора интерфейса.  
- Каждый стих — узел доступности с номером и языком.
- Навигация с клавиатуры по стиху, главе, книге.
- Сноски и ссылки доступны с клавиатуры.
- Объявления вида «Бытие, глава 3».
- Масштаб шрифта ОС, высокий контраст.
- Проверка — чек-лист на каждой программе.
Риск: в AccessKit (на нём держится Slint) пока нет rich text и hypertext.  
Это проверяется на пробном экране.  

(б) Чтение вслух — только русский и английский. Древние языки не озвучиваем.  
Порт «Речь» целиком: фрагмент с языком; пауза, продолжение, стоп; скорость и голос;  
события начала и конца фрагмента.  
В консоли MVP сделаны `say` (с обрывом текущего), `speaking` и `stop`.  
Текст готовит `speakable()`: стихи без сносок, ссылок и заголовков.  
Паузы, скорости, голоса, событий фрагмента, чисел и ссылок словами,  
ударений и пропуска иврита/греческого отдельным слоем ещё нет.  
Адаптеры системных синтезаторов через крейт tts (MIT): WinRT/SAPI 5, AVSpeechSynthesizer,  
Android TextToSpeech, Speech Dispatcher, позже Web Speech API.  
Сторонние голоса подключаются через ОС (RHVoice, голоса SAPI 5, движки Android).  
Ядро готовит текст:  
- что читать (номера, заголовки, сноски — настройками);
- ссылки и числа словами;
- словарь ударений для имён собственных;
- фрагменты по стихам и подсветка текущего стиха;
- вставки на иврите и греческом пропускаются.
На мобильных — фоновое чтение (служба переднего плана на Android, фоновый аудиорежим на iOS).  
После 1.0: необязательный офлайн-нейросинтез отдельным компонентом  
(espeak-ng под GPL — не внутри ядра); аудиобиблии как слой «аудио + метки стихов».  

## Расширения
Пять уровней — классификация, а не план.  
API v1:  
- данные от плагинов;
- пакетный конвейер вывода (на главу или экран);
- точки расширения UI, где рисует приложение.
Холст и собственный интерфейс плагина — после 1.0. Полная замена интерфейса —  
это альтернативный фронтенд через связку, а не плагин.  
Технология (WASM Component Model, Extism или декларативные плагины) выбирается к API v1.  
Версия API по SemVer, у плагина есть разрешения.  
iOS: исполняемые плагины не обещаем.  
Спецификация формата и API к API v1 пишется и на английском.  

## Сеть, репозитории, ИИ
Репозитории модулей: сейчас только основа — порт и описание индекса (JSON + SHA-256 + подпись).  
Реализация не скоро. Свой публичный репозиторий не ведём, пользователь подключает адрес сам.  
ИИ-перевод и анализ — необязательная функция далёкого будущего, включается только явно.  
Заметки никуда не отправляются.  

## Синхронизация
Экспорт и импорт zip. JSON — источник истины, у файла есть версия схемы.  
Markdown — только экспорт.  
У записи: id, updated_at, device_id, номер ревизии. Удаление записывается надгробием.  
Ничья решается детерминированно. При конфликте правок заметки сохраняются обе версии
(в реализации v1 упрощено до «побеждает свежее» — см. `docs/spec/06-user-data.md`).  
В схеме v1 нет версификации стиха и версии модуля; `user add` пишет пустой `context`
(открытый вопрос № 12).  
После 1.0: синхронизация через папку, которую выбрал пользователь (свой облачный диск, флешка).  
Нашего сервера нет.
