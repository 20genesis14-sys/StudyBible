# Лицензии модулей

Как лицензируются модули `.sb` / `.sbz`, что заявлено у встроенных
модулей и что обязан объявить новый модуль. Лицензия кода — отдельно,
см. [ADR 0002](adr/0002-licensing.ru.md) (`MIT OR Apache-2.0`,
«StudyBible contributors»).

## Принципы

- `.sb` / `.sbz` — контейнер (SQLite, опционально упакованный zstd —
  ADR 0016 §6). У контейнера лицензии нет; лицензия принадлежит
  **тексту/данным внутри**.
- Лицензия движка **не** распространяется на содержимое модулей, а
  лицензия модуля — на код.
- Каждый модуль несёт `license`, `attribution` и `source` в таблице
  `meta`; приложение показывает их пользователю. Модуль без
  заявленной лицензии считается **нераспространяемым**.
- Подробный юридический разбор текстов мы не ведём (ADR 0002), но
  модуль включается в поставку или публикуется только когда его
  статус задокументирован в этом файле.
- «Public domain» указывается только при подтверждении по источнику;
  иначе статус помечается *требует проверки*.

## Прочие модули

- `engwebp` и другие сконвертированные тексты: **только импорт
  пользователем** — исходники живут вне git в `STUDYBIBLE_DATA`, не
  коммитятся и не вкладываются. Статус фиксируется здесь до любой
  дистрибуции.
- Сторонние модули, импортируемые пользователем, — его
  ответственность; приложение показывает те `license`/`attribution`,
  которые объявил модуль.

## Требования к новому модулю

Прежде чем модуль вкладывается или публикуется, в `meta` и здесь
фиксируются:

1. `id`, название, язык (BCP 47), версия/дата.
2. `source` — откуда взят текст (URL/издание).
3. `license` — SPDX-идентификатор или короткая строка статуса;
   явный «public domain» — только при подтверждении.
4. `attribution` — строка указания авторства, если лицензия её
   требует (пустая, если нет).
5. Изменения, внесённые конвертером (нормализация, маппинг
   versification), если лицензия требует их отмечать.
6. Разрешение на распространение — вложение, сетевая раздача,
   использование ИИ.

Модуль, не проходящий проверку, не должен попадать в релизные
сборки; в исходной сборке F-Droid неясные модули исключаются
(`scandelete`) до подтверждения статуса.

## Заметки для F-Droid

Сканер F-Droid помечает бинарно выглядящие файлы; `.sbz`-модули —
данные, остающиеся в дереве исходников, потому что у каждого есть
заявленная лицензия в `meta` и строка в таблице выше. Актуальность
этого документа — обязательная часть добавления или обновления
любого встроенного модуля.
